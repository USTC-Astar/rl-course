# 第 17 课：仿真到现实

<div class="lesson-lead">
仿真器里的机器人质量精确、地面理想、传感器干净；真实机器人会磨损、延迟、打滑、受噪声干扰。最后一课学习怎样避免策略只会一个“完美电子游戏世界”。
</div>

## 本课主线

> 仿真到现实不是把仿真模型训练到最高分后直接部署，而是主动制造变化、评估未见扰动，并用安全工程逐级缩小现实差距。

## 1. 现实差距从哪里来？

**仿真到现实（Simulation-to-Reality, Sim-to-Real）**中的**现实差距（Reality Gap）**包括：

- 质量、惯量、摩擦系数建模不准；
- 电机响应延迟、死区和饱和；
- 传感器噪声、丢帧和时间不同步；
- 光照、材质、背景和相机参数变化；
- 碰撞、柔性、磨损等高阶现象被简化；
- 真实任务初始状态和异常情况覆盖不足。

策略可能不是学会“保持平衡”，而是学会利用仿真器某个精确摩擦系数或数值误差。

## 2. 域随机化怎样训练“一族世界”？

**域随机化（Domain Randomization）**在每个回合随机采样环境参数：

- 摆杆质量 0.7～1.3 倍；
- 摩擦 0.5～1.5 倍；
- 控制延迟 0～3 帧；
- 观测加入噪声和偏置；
- 相机光照、颜色、纹理和位置变化。

策略面对的不再是一个精确 MDP，而是一族相关环境。它被迫寻找对变化不敏感的共同规律。

类比学开车：如果只在同一天、同一辆车、同一条干燥道路练习，换到雨天和另一辆车容易失控；在多种车辆和天气下训练，适应性更强。

## 3. 随机化范围越宽越好吗？

不一定：

- 太窄：覆盖不了真实差距，策略仍过拟合标称仿真。
- 合理：包含真实系统可能范围，同时保持任务可学。
- 太宽：训练世界互相矛盾，策略为了兼顾极端情况变得过度保守，甚至学不会。

随机化范围应来自工程测量、历史数据和系统辨识，而不是随意把所有参数乘 0～10。

## 4. 系统辨识与域随机化是什么关系？

**系统辨识（System Identification, SysID）**用真实输入输出数据估计物理参数，例如质量、摩擦、延迟和电机常数。

两者可以配合：

1. 系统辨识找到最可能参数和不确定范围；
2. 仿真器以这些范围为中心做域随机化；
3. 真实测试暴露新误差；
4. 更新参数范围并重新训练。

系统辨识追求“仿真更像真实”，域随机化追求“策略不依赖仿真必须完全准确”。

## 5. 训练随机化与评估扰动必须分开

如果评估只使用训练见过的参数范围，你只能证明策略记住了随机化分布。

应准备三组环境：

- 标称环境：检查基本能力；
- 训练内扰动：检查随机化是否被学会；
- 训练外扰动：使用未见质量、延迟组合，检查真正泛化。

还要报告最差回报、失败率和恢复能力，不能只报平均分。

## 6. 奖励设计为什么在真实部署前要重审？

仿真中只奖励速度，智能体可能学会贴着碰撞边缘高速移动；仿真碰撞无成本，现实中可能损坏设备。

部署前应把隐含约束显式化：

- 动作幅度和变化率限制；
- 关节位置、速度、温度和电流限制；
- 碰撞和安全距离；
- 能耗、抖动和机械磨损；
- 失败后的恢复与急停。

奖励不是安全保证。硬约束、监控器和急停应独立存在。

## 7. 对应的可运行随机化代码

核心位于 `src/rl_learning_lab/advanced_lessons.py`：

```python
def sample_domain_parameters(
    seed,
    count,
    mass_range,
    friction_range,
    sensor_noise_standard_deviation,
):
    random_generator = np.random.default_rng(seed)
    return {
        "mass": random_generator.uniform(*mass_range, size=count),
        "friction": random_generator.uniform(*friction_range, size=count),
        "sensor_noise": random_generator.normal(
            0.0,
            sensor_noise_standard_deviation,
            size=count,
        ),
    }
```

生成 200 组可复现实验参数：

```bash
# 在项目根目录执行
./scripts/run_python.sh scripts/generate_advanced_lessons.py
```

在 Gymnasium 或 MuJoCo 中，可在每次 `reset()` 时把这些参数写入环境模型，然后执行仿真器的前向更新函数。

## 9. 从仿真到真实的安全阶梯

<ol class="step-list">
  <li>在标称仿真中达到基本任务目标。</li>
  <li>加入物理、观测、延迟和场景随机化。</li>
  <li>在训练外参数和故障注入环境中评估。</li>
  <li>导出策略并做动作范围、频率和推理延迟检查。</li>
  <li>真实设备上先空载、低速、限幅、有保护地测试。</li>
  <li>逐步扩大动作权限和任务范围，持续记录失败数据。</li>
</ol>

每一级失败都应返回上一层修正，不应跳过安全阶梯。

## 10. Isaac Sim、Gazebo、MuJoCo 怎样选择？

| 平台 | 强项 | 适合本课程后续方向 |
| --- | --- | --- |
| MuJoCo | 动力学快、强化学习生态成熟 | 机械控制算法原型、批量训练 |
| Gazebo / Gazebo Sim | 机器人操作系统生态、传感器和工程集成 | ROS 机器人软件联调 |
| Isaac Sim | 高质量视觉、GPU 并行、合成数据 | 视觉机器人、复杂场景和大规模并行 |
| PyBullet | 轻量、上手快 | 教学原型和简单控制 |

强化学习训练最重要的不是画面最漂亮，而是环境能否稳定、足够快地并行运行，并提供可信动力学与可控随机化。

## 11. 常见误区

- **仿真分数高就能部署。** 它只证明策略适应了当前仿真分布。
- **随机化越夸张越鲁棒。** 过宽分布会让策略学不到有效行为。
- **奖励里加碰撞惩罚就安全。** 安全还需要硬约束、监控和急停。
- **一次真实测试成功就完成迁移。** 需要多参数、多初始状态和长时间重复测试。

## 12. 动手练习

1. 为 Pendulum 设计质量、长度、摩擦、观测噪声四个随机范围。
2. 把训练随机化范围和测试范围故意错开，观察性能下降。
3. 写一份真实设备上线检查表，至少包含限幅、急停、日志和回滚。

## 14. 全课程总结

- 强化学习从状态、动作、奖励和价值开始。
- DQN 用函数逼近扩展到大状态空间，策略梯度直接学习动作分布。
- 行动者—评论家、PPO、SAC 和 TD3用不同方式平衡稳定、探索和样本效率。
- 多步回报、Double、Dueling、PER 和 Rainbow 是可组合的价值学习工具。
- Dyna-Q、多智能体、离线 RL 和仿真到现实把算法带入更真实的工程约束。

下一步建议：选择一个你真正关心的环境，把“训练目标、数据来源、评估指标和失败模式”写成一页项目设计，再决定算法，而不是先追最新论文名字。
