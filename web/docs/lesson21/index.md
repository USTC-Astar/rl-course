# 第 21 课：调试强化学习——当训练"不学习"时

<div class="lesson-lead">
强化学习代码很难写对：写错了 often 不报错，只是"学得慢一点"。本课用五个真实失败的训练曲线（由本项目脚本注入 bug 真实训练产生）建立"看曲线下诊断"的能力，并给出一套分层排查清单。

## 本课主线

> 调试强化学习的第一步不是改代码，而是建立"健康时曲线长什么样"的预期；第二步才是对照症状、逐层收窄：环境 → 数据 → 学习目标 → 优化器 → 评估。

## 1. 先有健康基线，才谈诊断

下表是同一环境（20% 打滑）下**健康 Q 学习**与四个**注入 bug 版本**的真实训练结果（各 2000 回合，`src/rl_learning_lab/debugging.py`，末 100 回合统计）：

| 场景 | 平均奖励 | 波动（标准差） | 成功率 |
| --- | ---: | ---: | ---: |
| 健康（ε 衰减，α=0.15，γ=0.95） | $7.61$ | $1.29$ | $100\%$ |
| bug A：ε 恒为 0（十种子最差者） | $3.96$ | — | 大幅下降 |
| bug B：更新了错误动作的 Q | $3.20$ | $5.65$ | $82\%$ |
| bug C：α = 1.0 | $3.61$ | $7.99$ | $84\%$ |
| bug D：γ = 0.3 | $6.35$ | $4.89$ | $95\%$ |

注意症状各不相同：B 是"均值大降+波动翻四倍"，C 是"波动翻六倍但均值尚可"，D 是"轻微变差"，A 是"换个种子就好了"。**曲线形态本身就是线索。**

## 2. 案例库：五个真实失败

### 案例 A：不是所有失败都稳定复现——ε = 0

关掉探索（ε 恒为 0）跑了 10 个种子，末段平均奖励：

$$
[\,3.96,\ 7.54,\ 7.69,\ 7.82,\ 7.86,\ 7.89,\ 7.92,\ 7.97,\ 8.03,\ 8.04\,]
$$

**症状**：十个种子里九个完全正常，一个卡在 3.96——"我的代码有时能学有时不能"。
**诊断**：这种"时好时坏"几乎总是**探索不足或初始化运气**。初始 Q 全零时靠随机平局打破来乱走，走到终点的种子顺藤摸瓜学出来；没走到的种子守着一张半空的表反复走老路。
**修复**：恢复 ε 衰减（1.0 → 0.05）；下结论前**至少跑 3—5 个种子**。
**教训**：单种子的成功或失败都不算证据。

### 案例 B：均值大降 + 波动翻倍——更新了错误的槽位

一行经典笔误：想把 TD 误差写回"实际执行的动作"，却写成了"当前表上最优的动作"：

```python
# 错：更新的是 argmax 槽位，与实际执行的动作脱钩
update_slot = int(np.argmax(q_table[state]))
# 对：更新实际执行的动作
update_slot = action
```

**症状**：平均奖励 7.61 → 3.20，波动 1.29 → 5.65。策略与价值表互相脱钩：表在"改进一个想象中的策略"，执行的却是另一个。
**诊断线索**：波动比均值下降更早出现；在确定性环境（无打滑）里这个 bug 甚至**几乎无症状**——又是一个"环境宽容掩盖 bug"的例子。
**修复**：单元测试覆盖更新式（本项目 `tests/` 对每课核心计算都有测试，就是为这类 bug 准备的）。

### 案例 C：波动爆炸、均值勉强——学习率 α = 1.0

**症状**：波动 1.29 → 7.99（六倍），平均 7.61 → 3.61。曲线呈现"学会→崩回去→再学"的锯齿。
**诊断**：α=1 意味着 Q 值被每次采样的目标**完全覆盖**。打滑环境下每次目标本身带噪声，噪声毫无衰减地写进表里；α=0.15 时单次噪声被稀释 85%。
**修复**：降回 0.05—0.3 区间；更一般地，**先固定其他一切、只动学习率一个旋钮**观察曲线形态。

### 案例 D：轻微变差 + 轻微波动——γ = 0.3 短视

**症状**：均值 6.35、波动 4.89，看似"也还行"。
**诊断**：$\gamma=0.3$ 时 10 步外的 +10 折成 $10 \times 0.3^{10} \approx 0.0006$——终点几乎不可见，策略只对眼前 2—3 格的得失敏感，路线忽左忽右。
**教训**：**不是所有 bug 都表现为彻底失败**；"学是学了但总差一点"要看折扣因子、奖励尺度和终止条件这类"世界观参数"。

### 案例 E：没发作的 bug——终止态自举

第 1 课反复强调"终止后 bootstrap 必须置零"。我们真的注入了这个 bug（终止后仍加 $\gamma\max Q(s‘)$）在**本表格环境**里跑：**结果与健康版完全一样**。原因：终止格（终点/陷阱）永远不会作为"当前状态"被行动，它的 Q 行恒为零，加进来的 $\gamma \cdot 0$ 等于没加。
**这个"没发作"本身就是最重要的诊断知识**：同一个 bug 换个实现就会致命——在深度网络里，网络对**任何**输入（包括终止状态）都输出非零值，终止自举会通过目标网络不断把虚增的未来价值泵回整个表，训练中期突然崩盘。**bug 是否发作取决于环境与实现的组合**，"在我的小测试里没事"不等于"没事"。

## 3. 分层排查清单

按"从便宜到昂贵"的顺序排查，每层通过再进下一层：

<ol class="step-list">
  <li><strong>环境层</strong>：随机策略能拿到非零奖励分布吗？打印一条人工轨迹，奖励、终止、越界符合预期吗？观测维度、动作空间和文档一致吗？</li>
  <li><strong>数据层</strong>：回放池里 (s, a, r, s’, done) 五元组抽样打印 10 条，人工核对 done 标志；状态归一化前后一致吗？</li>
  <li><strong>目标层</strong>：手算一个 batch 的 TD 目标与代码输出对数；终止态目标确实为 r 吗；损失对参数的梯度非零吗（梯度全零 = 图断开）。</li>
  <li><strong>优化层</strong>：学习率先取保守值（如 1e-4—3e-4 网络场景）；梯度裁剪生效吗；Q 值幅值在膨胀吗（高估/发散的早期信号）。</li>
  <li><strong>评估层</strong>：关掉探索单独评估贪心策略；多种子；报告均值±波动而不是单条曲线的最高点。</li>
</ol>

::: tip 最有用的三个习惯
1. **先跑通最小可学习任务**（本项目的 6×6 网格就是为此存在），再迁移到真任务。
2. **任何"学得慢"先怀疑 bug，再怀疑超参数**——案例 B 的笔误在调参人手里会变成"学习率调了三天"。
3. **核心计算单元测试**：本项目 `tests/` 目录对每课的核心更新式都有测试；新算法先让测试过，再上训练。
:::

## 6. 常见误区

- **"训练不动就是学习率太小。"** 案例 B/C/D 各有病因；先看波动形态和 Q 值幅值，再动学习率。
- **"我的小测试通过了，实现就是对的。"** 案例 E 的 bug 在表格环境无症状、在深网里致命。测试要通过**接近真实结构**的用例。
- **"这条曲线最后涨到高分，方法有效。"** 单种子单曲线的最高点不是证据；要看多种子的平均与波动。
- **"随机种子只是工程细节。"** 案例 A 里它是决定成败的唯一变量。

## 7. 动手练习

1. 在 `train_with_bugs` 里新增一个 bug：`done` 判断写反（非终止时置零、终止时自举），训练并描述症状。
2. 把打滑 `SLIP` 改成 0，重跑四个 bug 场景：哪些 bug 的症状消失了？解释原因（对照案例 B/E）。
3. 对案例 A 的失败种子（找到是哪一个），单独把 ε 改成 0.1 再跑：能救回来吗？

## 9. 本课只需要记住这些

- 先建立健康基线的预期，再谈诊断；曲线形态（均值 vs 波动）是第一线索。
- "时好时坏"查探索与种子；"波动爆炸"查学习率与目标噪声；"轻微变差"查折扣与奖励尺度；"突然崩盘"查终止处理与自举。
- 有的 bug 在宽容环境里不发作——测试要贴近真实结构，单元测试核心更新式。
- 多种子、独立评估、报告波动，是任何"我学会了"结论的底线。
