Q-LEARNING

Q 学习：给每个“处境 + 动作”建立经验分数

🍜

Q 值就像你的餐馆经验表

“周一中午去 A 店”可能评分 8，“下雨天去 B 店”可能评分 3。Q 值不是餐馆永远的绝对分数， 而是描述在某种情况下做某个选择，长期来看有多划算。

Q(s,a) ← Q(s,a) + α [r + γ max Q(s′,a′) − Q(s,a)]

不要背。把它拆成一句话：

新评价=旧评价+学习速度×这次发现的误差

学习率（Learning Rate, α）

一次新经历能改变旧看法多少。太大容易反复横跳，太小学得很慢。

折扣因子（Discount Factor, γ）

未来奖励的重要程度。接近 1 表示愿意为了将来的终点暂时承受小损失。

探索率（Exploration Rate, ε）

随机尝试陌生动作的概率。开始时高，经验变多后逐渐降低。

训练初期像第一次进商场：到处看看ε 接近 1
训练中期知道几家好店，但偶尔尝新ε 逐渐下降
训练后期大多数时候选择经验最好的路线ε 接近 0.05
查看核心 Q 学习代码 
# 1. 用 ε-贪心策略决定：探索新动作，还是使用当前经验
action = choose_action(q_table, state, epsilon, rng)

# 2. 真正在环境里走一步，获得结果
next_state, reward, done = env.step(action)

# 3. 终局之后没有未来，因此未来价值记为 0
best_next_value = 0.0 if done else np.max(q_table[next_state])

# 4. “眼前奖励 + 未来最好前景”组成新的学习目标
target = reward + discount_factor * best_next_value

# 5. 不一次性推翻旧经验，只向新目标靠近一点
error = target - q_table[state, action]
q_table[state, action] += learning_rate * error

→
神经网络128 → 128

📐

从“背答案”变成“学规律”

Q 值表像背下每一道题的答案；神经网络像学会解题方法。即使遇到没见过的角度， 只要与过去情况相似，也能估算应该向哪边推。

经验回放（Experience Replay）

把经历存进“错题本”，训练时随机抽取。这样不会只盯着刚刚发生的几步，也能让同一条经验被重复利用。

AFCHB

目标网络（Target Network）

在线网络不断学习，目标网络暂时固定参考答案。如果出题人和答案同时快速变化，学生很难稳定学习。

在线网络定期复制目标网络
查看深度 Q 网络的核心更新 
# 在线网络给出当前执行动作的 Q 值
current_values = online_network(states).gather(1, actions)

# 目标网络提供相对稳定的未来价值
with torch.no_grad():
    next_actions = online_network(next_states).argmax(dim=1, keepdim=True)
    next_values = target_network(next_states).gather(1, next_actions)

# 让当前预测逐渐接近目标，而不是手工填写 Q 值

PROJECT THREE

同一个小车，换个大脑：直接学习动作概率

深度 Q 网络先问“向左和向右分别值多少分”，再选择分数高的动作。 策略梯度（Policy Gradient）不再绕这一步，而是直接回答：“现在向左和向右各有多大概率？”

VALUE-BASED

深度 Q 网络的思路

状态→两个 Q 值→选择最大值

像先给每道菜打分，再点分数最高的菜。

POLICY-BASED

策略梯度的思路

状态→动作概率→按概率行动

像直接形成点菜习惯：面食 70%，米饭 30%。

🏀

教练没有逐帧标准答案

球员完成一套动作后得分，教练会提高这套成功动作再次出现的倾向；如果最终失败，就降低相关动作的倾向。 策略梯度也是根据整段经历的回报，调整每一步动作的概率。

∇J(θ) ≈ Σ Gₜ ∇ log πθ(aₜ | sₜ)

先不背符号，把它翻译成三步：

看看这一段最终回报→ 找到当时选择动作的概率→ 好结果就提高概率，差结果就降低概率

策略（Policy, π）

从当前状态得到动作概率分布。本项目输出向左和向右两个概率，两者相加等于 100%。

折扣回报（Discounted Return, Gₜ）

从当前动作开始，未来奖励的折扣总和。越早帮助小车长期站稳的动作，通常获得越高评价。

熵（Entropy）

衡量策略有多随机。少量熵奖励能防止网络太早变成“无论什么情况都只向同一边推”。

第 1 步未来还能坚持 200 步这一步可能很重要
第 150 步未来还能坚持 50 步仍有贡献，但可见未来更短
最后一步下一刻杆就倒了这一步得到的长期回报较少
查看 REINFORCE 策略梯度核心代码 
# 1. 神经网络直接给出动作分布，并按照概率采样
distribution = Categorical(logits=policy_network(observation))
action = distribution.sample()

# 2. 回合结束后，从后向前计算每一步的折扣回报
returns = discounted_returns(rewards, discount_factor)

# 3. 高回报动作提高概率，低回报动作降低概率
log_probabilities = distribution.log_prob(actions)
policy_loss = -(log_probabilities * returns).mean()

# 4. 加少量熵奖励，避免策略过早失去探索能力
loss = policy_loss - entropy_coefficient * distribution.entropy().mean()
为什么代码同时训练 16 辆小车？

这叫向量环境（Vectorized Environment）。算法没有改变，只是让 16 辆小车同时收集完整回合， 再合并更新一次策略。像让全班同时做题，比一个学生连续做 16 份试卷更快，也能降低单次运气的影响。

PROJECT FOUR

行动者-评论家：一个负责行动，一个负责评价

REINFORCE 要等完整回合结束，才知道这一整段动作表现如何。行动者-评论家（Actor-Critic）增加一个评论家， 在训练过程中持续估计当前局面的前景，让行动者获得更及时的反馈。

ACTOR
🏃

行动者（Actor）

看到当前状态，输出向左和向右的动作概率，然后真正控制小车。

选择动作 → 环境产生新结果 ← 优势值反馈
CRITIC
🧑‍🏫

评论家（Critic）

看到当前状态，估计从这里开始未来大概还能获得多少回报。

⛹️

运动员不必等整场比赛结束才听教练说话

纯策略梯度像比赛结束后只得到一句“赢了”或“输了”；行动者-评论家则像教练在每个回合间告诉运动员： “刚才这次选择比我预期好 20 分”，反馈更及时，也更容易判断具体动作的贡献。

A(s,a) = Gₜ − V(s)

优势值（Advantage）不是问动作绝对有多好，而是问它比评论家的预期好多少。

评论家预计100
→
实际回报140
=
优势值+40提高动作概率
评论家预计100
→
实际回报60
=
优势值-40降低动作概率

状态价值（State Value, V）

评论家对当前局面前景的估计。杆接近竖直且运动稳定时，通常应该给出更高价值。

时序差分误差（Temporal-Difference Error）

比较“奖励加下一状态价值”和当前预测的差距，帮助评论家逐步纠正自己的判断。

广义优势估计（Generalized Advantage Estimation, GAE）

综合几种不同长度的未来信息，在反应速度和估计稳定性之间取得折中。

为什么只向前看 5 步？

每走一步就更新，反馈及时但容易被偶然噪声影响；等完整回合再更新，比较稳定但反馈太慢。 本项目每 5 步汇总一次，再由评论家估计更远的未来，相当于“看清眼前几步，同时参考长期判断”。

真实观察 5 步
12345＋ 评论家预测未来
查看行动者-评论家核心更新 
# 同一批状态分别送给行动者和评论家
action_logits, state_values = network(observations)
distribution = Categorical(logits=action_logits)

# 用真实奖励和评论家预测计算广义优势估计
advantages, return_targets = calculate_gae(
    rewards, dones, state_values, bootstrap_values
)

# 行动者：优势为正就提高该动作概率，优势为负就降低
actor_loss = -(log_probabilities * advantages.detach()).mean()

# 评论家：让自己的价值预测接近实际回报目标
critic_loss = mse_loss(state_values, return_targets)

# 两个目标一起优化，同时保留少量策略随机性
loss = actor_loss + 0.5 * critic_loss - 0.001 * entropy
训练分数高，不代表当前模型一定好

训练过程中策略不断变化，一个长回合可能跨越多次更新。因此项目会定期暂停训练进行独立考试，并保留考试成绩最好的模型， 而不是简单保存最后一次更新。这是本节从实际调试中得到的重要经验。

PROJECT FIVE

PPO：给策略更新装上限速器

上一课已经看到：行动者-评论家可能一次更新就把不错的策略推坏。 近端策略优化（Proximal Policy Optimization, PPO）的核心不是更复杂地预测未来， 而是限制新策略不要一次离旧策略太远。

🚗

高速行驶时，方向盘不能一次打满

普通行动者-评论家像看到车偏了一点，就可能猛打方向盘；PPO 像加入转向限速器，每次只允许有限修正。 它不禁止策略进步，只是不让一次偶然经验把整个行为方式推翻。

旧策略 向右 40% 收集经验时的概率
→
新策略 向右 60% 训练几轮后的概率
概率比 60% ÷ 40% = 1.5 PPO 会按上限 1.2 进行优化
rₜ(θ) = πnew(aₜ|sₜ) ÷ πold(aₜ|sₜ)
0.81.2

当裁剪系数是 `0.2` 时，PPO 重点关注概率比 `0.8～1.2` 的安全区间。 超出区间后，继续把策略推得更远不会获得额外优化收益。

概率比（Probability Ratio）

同一个动作在新旧策略下的概率之比。1 表示没有变化，1.2 表示概率增加约 20%。

裁剪（Clipping）

把优化收益限制在安全区间，避免行动者被一批偶然的高优势样本推得太远。

训练轮次（Epoch）

同一批经验可以重复训练多轮，但每轮都使用旧概率作为参照，裁剪负责控制变化。

近似 KL 散度（Approximate KL Divergence）

衡量新旧策略整体差异。数值突然变大通常表示更新过猛，需要降低学习率或训练轮数。

1用旧策略收集 128 步保存状态、动作和旧概率
2评论家计算优势值判断动作比预期好多少
3切成小批量训练 4 轮提高一批经验的利用率
4裁剪概率比限制单次策略变化
查看 PPO 裁剪更新核心代码 
# 新旧策略对同一个动作的概率比
ratio = exp(new_log_probability - old_log_probability)

# 普通目标：优势为正时，希望提高该动作概率
unclipped = advantage * ratio

# 安全目标：把概率比限制在 0.8 到 1.2
clipped = advantage * clamp(ratio, 0.8, 1.2)

# 选择更保守的收益，避免策略一次改变过大
actor_objective = minimum(unclipped, clipped)
actor_loss = -actor_objective.mean()
PPO 为什么可以重复使用同一批经验？

普通策略梯度在策略更新后，旧经验很快就与新策略不匹配。PPO 保存收集经验时的旧概率， 每次更新都计算新旧概率比，并用裁剪阻止偏离过大，因此能够相对安全地对同一批经验训练多轮。

第一步：先理解“旧经验为什么会过期”

收集经验时

旧策略像原来的司机

PPO 的“重复使用”很有限，不等于经验回放

PPO 通常只把同一批经验训练几轮，然后立刻丢弃；它不能把几小时前、几十个旧策略产生的数据长期混在一起训练。 因此 PPO 仍属于同策略方法（On-Policy Method）。第七课的 SAC 属于异策略方法（Off-Policy Method）， 才会把来自许多旧策略的经验长期保存在回放池里反复抽取。

PROJECT SIX

连续动作控制：不再只选左右，而是决定推多大力

前五个项目使用离散动作空间（Discrete Action Space），动作都像按按钮：向左或向右。 真实机器人却经常要控制油门、转矩、舵角和关节力度，因此需要连续动作空间 （Continuous Action Space）。本课使用 MuJoCo 的倒立摆环境，让智能体输出 -3.0～+3.0 之间的任意推力。

🚰

离散动作像电灯开关，连续动作像水龙头

电灯开关通常只有“开”和“关”，这就是离散动作；水龙头却能拧到 10%、35% 或 82%， 这就是连续动作。控制倒立摆时，只会“全力向左或全力向右”太粗暴，智能体还要学会轻推和收力。

比较问题离散动作空间连续动作空间
可选动作有限个按钮，例如左、右一个区间内的任意数值
策略输出每个按钮的概率动作分布的均值与标准差
生活例子选电梯楼层、下棋落子踩油门、转方向盘、关节发力
本课动作不再使用-3 向左，+3 向右

环境

MuJoCo 倒立摆

MuJoCo 负责计算小车、杆、重力和接触等物理变化；智能体只读取 4 个状态数值。

动作

单维连续推力

负数向左推，正数向右推，绝对值代表力度；例如 +0.4 是轻推，-2.8 是用力左推。

奖励

每坚持一步得 1 分

杆没有倒下就继续得分，最多坚持 1000 步。因此回报 1000 表示完成整场挑战。

为什么状态仍然只有 4 个数，动作却变难了？

难点不只在“看见什么”，还在“怎样表达选择”。以前网络只需比较两个按钮；现在动作有无限多个可能值， 不可能给每个小数都单独输出一个概率，所以我们让网络输出一个概率分布。

高斯策略：先说“想推多少”，再说“愿意尝试多远”

高斯策略（Gaussian Policy）通常输出两个核心数：均值（Mean, μ）与标准差 （Standard Deviation, σ）。它们共同组成高斯分布（Gaussian Distribution）： 均值决定动作中心，标准差决定探索范围。

μ = +1.2

均值决定主要方向

网络当前认为“向右推 1.2”最合适。可以把它理解为司机此刻最想踩到的油门位置。

σ = 0.15

小标准差：更有把握

采样大多靠近 +1.2，行为稳定，但很少尝试其他力度，可能错过更好的动作。

σ = 1.20

大标准差：更爱探索

有时轻推，有时重推，能发现新办法，但训练轨迹也更容易摇晃甚至失败。

u ∼ Normal(μ, σ)　→　y = tanh(u)　→　a = 3y
高斯分布采样原始动作 u→压到 -1～+1→映射为 -3～+3 的推力

双曲正切函数（Hyperbolic Tangent, tanh）像一条带护栏的道路：无论原始动作多大， 输出都不会越过 -1 和 +1。再乘以 3，就能保证 MuJoCo 收到的动作永远合法。

1网络输出 μ、σ例如 μ=0.4，σ=0.8
→
2采样原始动作这一次可能抽到 u=1.1
→
3tanh 压缩tanh(1.1)≈0.80
→
4映射到环境0.80×3≈+2.4
查看高斯采样、动作压缩和 PPO 更新核心代码 
# 1. 行动者给出高斯分布的中心与宽度
action_mean, action_std, state_value = network(observation)
distribution = Normal(action_mean, action_std)

# 2. 训练时随机采样，让策略能探索不同力度
raw_action = distribution.rsample()

# 3. tanh 把无限范围压缩到 -1～+1，再映射到 -3～+3
squashed_action = tanh(raw_action)
bounded_action = action_bias + action_scale * squashed_action

# 4. 压缩会改变概率密度，因此对对数概率做雅可比修正
correction = log(action_scale * (1 - squashed_action²) + 1e-6)
log_probability = distribution.log_prob(raw_action) - correction

# 5. PPO 仍比较新旧策略对“同一个连续动作”的对数概率
ratio = exp(new_log_probability - old_log_probability)
actor_loss = clipped_ppo_loss(ratio, advantage)
概率不再是“这个动作占 60%”

连续数值中，精确抽到 1.200000... 的概率几乎为零，因此连续策略使用概率密度 （Probability Density）和对数概率（Log Probability）。你可以把概率密度理解为： 某个动作附近有多拥挤、多容易被抽到。PPO 比较的仍是新旧策略对已执行动作的相对偏好。 tanh 改变了这种密度，因此代码还要使用雅可比修正（Jacobian Correction）把概率账本改正确。

为什么“精确抽到 1.2”的概率是零？

离散情况

抽扑克牌可以问“正好是哪一张”

一副 52 张牌中，抽到红桃 A 的概率是 1/52，因为所有可能结果可以一张张数出来。

连续情况

测身高不能只问“正好多少”

身高可能是 170、170.1、170.01、170.001……小数可以无限细分，精确等于 170.000000... 的单点概率为零。

正确问法

问一个小区间的概率

例如“身高在 169.5～170.5 厘米之间”。概率密度越高，这段区间下方的面积越大，被抽到的概率也越大。

区间概率 ≈ 该处概率密度 × 区间宽度
密度 0.30×宽度 0.10=概率约 0.03
密度 0.05×宽度 0.10=概率约 0.005

密度本身不是百分比，甚至可能大于 1；真正必须落在 0～1 之间的是某个区间下方的总面积。

为什么代码偏爱“对数概率”？

直接相乘 0.001 × 0.002 × 0.0005 × …

一长串很小的概率相乘，很快会小到计算机只能记成 0，这叫数值下溢（Numerical Underflow）。

取对数后 log 0.001 + log 0.002 + log 0.0005 + …

乘法变成加法，数值不容易消失；新旧概率相除也能写成 exp(new_logp - old_logp)。

雅可比修正到底在修正什么？

📏

把 tanh 想成一把被挤压的橡皮尺

原始动作轴从负无穷延伸到正无穷，tanh 把整条轴塞进 -1～+1。靠近 0 的刻度较宽，靠近两端的刻度被挤得很密。 同样数量的样本被塞进更窄的动作区间后，局部概率密度必然改变，不能继续沿用压缩前的数字。

原始动作 u = 0 a = 3·tanh(0) = 0

局部斜率约为 3，原始坐标的一小段映射后仍比较宽，挤压不明显。

原始动作 u = 2 a ≈ 3·0.964 = 2.89

局部斜率只剩约 0.21，同样宽度被压到约十四分之一，动作密度会因此改变。

变换后的密度 p(a) = p(u) ÷ |da/du|

代码在对数空间中写成“原始对数密度减去斜率的对数”，这就是雅可比修正。

训练阶段

随机策略（Stochastic Policy）

读取 μ、σ→随机采样→探索不同推力

假设 μ=0.4、σ=0.8，这一帧可能抽到 -0.2，下一帧可能抽到 1.1。训练回报可能忽高忽低， 因为策略故意用这些随机偏差寻找更好的推力。

评估阶段

确定性动作（Deterministic Action）

读取 μ→计算 3·tanh(μ)→稳定执行

网页执行的是压缩后的中心动作 3·tanh(μ)。严格来说，它不一定等于变换后分布的数学期望， 但它稳定、可重复，适合回答“策略中心学会没有”。

PROJECT SEVEN

SAC：把旧经验放进错题本，隔很久仍能反复学习

上一处疑问的答案是：PPO 只能在策略变化不大时，短暂重复使用同一批经验。 软行动者-评论家（Soft Actor-Critic, SAC）换了一条路线：它学习动作价值 Q(s,a)， 因此可以从经验回放池中抽取许多旧策略留下的数据，属于异策略方法（Off-Policy Method）。

📚

PPO 像当堂订正，SAC 像长期错题本

PPO 收集一页练习，当堂订正四遍，然后把纸丢掉；SAC 把每道题都存进错题本， 今天可以抽到昨天的题，下周也可能再次抽到。这样每次与环境交互得到的经验能发挥更多次作用。

比较问题PPOSAC
方法类别同策略：数据要接近当前策略异策略：允许来自许多旧策略
经验保存一批 rollout 用几轮后丢弃长期放入经验回放池
主要修正办法新旧概率比与裁剪学习 Q(s,a)，用 Bellman 目标训练
样本效率通常需要不断采集新数据同一条经验可能被抽到很多次

这次控制什么：Pendulum 摆锤

状态 1、2

cos θ 与 sin θ

用圆上的横坐标和纵坐标表示角度，避免 +π 与 -π 在数值上突然跳变。

状态 3

告诉智能体摆锤正在向哪边转、转得多快；只看角度无法判断下一刻的运动趋势。

动作

负数逆时针发力，正数顺时针发力。智能体要学会先荡起来，再在顶部减速稳定。

奖励 = -(角度误差² + 0.1·角速度² + 0.001·转矩²)

这次奖励是负数，越接近 0 越好。摆锤倒挂、旋转过快、用力过猛都会扣分。 就像体操评分：站到顶部只是第一步，还要稳、还要动作干净。

经验回放池：为什么旧数据现在能长期使用？

s₁,a₁,r₁,s₂s₂,a₂,r₂,s₃s₇,a₇,r₇,s₈ s₃,a₃,r₃,s₄s₉,a₉,r₉,s₁₀s₄,a₄,r₄,s₅

随机抽取，而不是只看刚发生的顺序

连续相邻的画面很相似，像连续看十张几乎一样的照片。随机抽样会把不同时间、不同旧策略、 不同角度的经验混在一个小批量中，让神经网络看到更丰富、更稳定的数据。

关键区别：SAC 学的是动作价值，而不是复刻旧策略的动作概率

一条旧经验告诉评论家：“在状态 s 做动作 a，得到了奖励 r，并到达 s′。” 这个物理事实不会因为当前策略变了就失效。评论家可以反复用它校正 Q(s,a)， 行动者再去寻找当前 Q 值高、同时保留适度随机性的动作。

为什么要有两个 Q 网络？

评论家 1

Q₁(s,a) = 82

第一个估价员认为这个动作长期价值很高。

取较小值
评论家 2

Q₂(s,a) = 67

第二个估价员更谨慎，只给出 67。

min(Q₁,Q₂) = 67
🏠

双 Q 网络像请两位房屋估价师，然后采用较低报价

单个神经网络有时会因为数据噪声过度乐观。行动者若总追逐被高估的动作，错误会自我强化。 双评论家（Twin Critics）取较小值，不能保证永远正确，但能明显减少价值过高估计。

目标 y = r + γ[min(Q′₁,Q′₂) - α log π(a′|s′)]
r刚得到的奖励 min Q′下一状态的保守未来价值 -α log π保留随机性的熵奖励

评论家让自己的 Q(s,a) 靠近这个目标；这就是 SAC 能从回放池旧经验学习的核心。

“软”字来自哪里：不仅追求高回报，也奖励适度随机

只追求 Q 值

很快认定一种动作

可能过早锁死在局部方案，例如只会向一个方向猛甩，遇到不同初始角度就失败。

温度 α 回报 ← 平衡 → 随机性 自动调节
加入策略熵

保留多种可行动作

在多个动作价值接近时不要太早押注，继续探索，往往能学到更稳健的摆起方式。

温度 α 不是环境温度

温度参数（Temperature Parameter, α）控制“随机性值多少钱”。α 大时更重视探索，α 小时更重视高 Q 动作。 本项目让 α 自动学习：策略太确定就升高探索压力，太随机就降低探索压力，像恒温器自动调节暖气。

目标网络为什么只慢慢移动？

在线 Q 参数100%每次梯度更新都会变化
τ = 0.005
目标 Q 新参数0.5% 在线 + 99.5% 旧目标缓慢跟随，提供稳定学习目标
1与环境交互一步得到 s、a、r、s′
2存入回放池新旧策略经验混合保存
3随机抽取小批量训练两个 Q 网络
4更新行动者与 α兼顾高价值和适度随机
5软更新目标网络只向在线 Q 靠近一点

# 从长期错题本随机抽一批旧经验
states, actions, rewards, next_states, dones = replay_buffer.sample(batch_size)

# 双目标评论家采用较小值，并减去温度控制的对数概率
next_action, next_logp = actor.sample(next_states)
next_q = minimum(target_q1(next_states, next_action),
                 target_q2(next_states, next_action))
q_target = rewards + gamma * (1 - dones) * (next_q - alpha * next_logp)

# 两个评论家都学习同一个保守目标
critic_loss = mse(q1(states, actions), q_target)
critic_loss += mse(q2(states, actions), q_target)

# 行动者寻找 Q 值高、同时不过早失去随机性的动作
new_action, logp = actor.sample(states)
actor_loss = (alpha * logp - minimum(q1(states, new_action),
                                    q2(states, new_action))).mean()

# 目标网络只跟随 0.5%，避免学习目标剧烈晃动
target_q = 0.995 * target_q + 0.005 * online_q
